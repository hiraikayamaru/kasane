# 自作CPU 設計仕様（暫定）

- **文書バージョン**：0.1（設計メモ）
- **状態**：仮採用。実装・テストによる検証前
- **目的**：自作プログラミング言語を自作コンパイラで独自アセンブリに変換し、自作アセンブラ・CPUエミュレーターで実行する。
- **設計方針**：CPU内部を比較的単純に保ち、関数呼び出し・スタック管理などの高水準の仕組みは主にコンパイラと呼び出し規約で実現する。

> **この文書の読み方**：これまでの会話で仮採用した内容を一つにまとめた。命令の振る舞いを再現可能にするため、一部に「v0.1での作業上の仮定」を加えた。未決定事項は末尾に分離してある。**確定済みの製品仕様ではない。**

## 1. 全体構成と到達目標

```text
自作言語のソースコード
        ↓ コンパイラ
独自アセンブリ
        ↓ アセンブラ
32ビット命令の機械語
        ↓ CPUエミュレーター
実行結果（整数出力など）
```

最初の到達目標は、整数変数・四則演算・`if`・`while`・関数呼び出し・再帰・配列を持つ小規模なコンパイル型言語を動作させること。乗算や除算は最初から専用命令を設けず、必要ならライブラリで実装する。最初の検証は整数の合計や関数呼び出しを使うプログラムで行う。

## 2. CPUの基本仕様

| 項目 | 暫定仕様 |
|---|---|
| アーキテクチャ | 16ビットのレジスタ型・load-store型 |
| 汎用レジスタ | `R0`～`R7`、各16ビット |
| 専用レジスタ | `PC`（16ビット）のみ |
| 命令長 | **32ビット固定長**（1命令 = 4バイト） |
| アドレス幅 | 16ビット |
| メモリ | 64 KiB（アドレス `0x0000`～`0xFFFF`） |
| アドレス単位 | 1バイト（byte-addressed） |
| 命令・データ空間 | 共通のアドレス空間（フォン・ノイマン型の単純なモデル） |
| バイト順 | リトルエンディアン（16ビットデータ、32ビット命令） |
| 16ビットメモリアクセス | 偶数アドレスのみ許可 |
| 条件フラグ | なし。分岐命令がレジスタを直接比較する |
| スタック | 通常メモリ上、低位アドレス方向へ成長 |
| 入出力 | 当面はエミュレーターの `TRAP` サービス |

`R0` は定数ゼロに固定せず、通常の汎用レジスタとして扱う。命令メモリとデータメモリの間にハードウェアによるアクセス保護は**設けない想定**。メモリ内のコード・データ・スタックの境界は現段階では固定しない。

### 2.1 レジスタのソフトウェア上の使い分け（呼び出し規約の草案）

| レジスタ | 想定する役割 | 備考 |
|---|---|---|
| `R0` | 第1引数・戻り値 | 呼び出し先が変更可 |
| `R1`～`R3` | 引数・一時値 | 呼び出し先が変更可 |
| `R4`～`R5` | 呼び出しをまたいで維持する値 | **保存規約は要確定**（callee-saved案） |
| `R6` | リンクレジスタ（戻り先アドレス） | 関数がさらに関数を呼ぶなら退避が必要 |
| `R7` | スタックポインタ（SP） | コンパイラ／プログラムの慣例でありCPU専用ではない |
| `PC` | 実行中の命令アドレス | CPU専用 |

CPU自体は `R6` や `R7` に特別な意味を与えない。`SP`、`FP`、`CALL`、`RET`、`PUSH`、`POP` のための専用回路や専用命令は当初設けない。

## 3. アドレッシングとメモリ操作

採用する主な指定方法：

- **レジスタ**：`ADD R2, R0, R1`
- **即値**：`LDI R0, 42`、`ADDI R0, R0, -1`
- **ベース＋符号付きオフセット**：`LD16 R0, [R1 + 4]`
- **レジスタ間接**：`LD16 R0, [R1]`（オフセット0の場合）
- **PC相対分岐**：`BEQ R0, R1, label`、`JMP label`
- **レジスタ指定のジャンプ先**：`JR R6`、`JALR R6, R2`

以下は、当初は専用形式として実装しない：絶対アドレスを直接使うメモリ命令、ベース＋インデックスの複合指定、スケール付きインデックス指定。必要なら複数の基本命令で合成する。

16ビットの実効アドレスは、`a = (R[base] + sign_extend(imm)) mod 2^16` とする。`LD16` と `ST16` は `a` が偶数であることを要求する。読み込み値は `M[a] + 256 * M[a+1]`。`LD8` はゼロ拡張、`ST8` はソースレジスタの下位8ビットのみ保存する。

## 4. 32ビット命令の共通フィールド

ビット31を最上位ビット、ビット0を最下位ビットとする。

```text
31    30 29       25 24    22 21    19 18    16 15               0
+-------+-----------+--------+--------+--------+------------------+
|  fmt  |    op     |   A    |   B    |   C    |       imm        |
+-------+-----------+--------+--------+--------+------------------+
   2 bit    5 bit      3 bit    3 bit    3 bit        16 bit
```

| フィールド | ビット | 内容 |
|---|---|---|
| `fmt` | 31～30 | 命令形式（2ビット） |
| `op` | 29～25 | 形式内オペコード（5ビット） |
| `A` | 24～22 | レジスタ番号等 |
| `B` | 21～19 | レジスタ番号等 |
| `C` | 18～16 | レジスタ番号等 |
| `imm` | 15～0 | 16ビット即値・相対変位等 |

`fmt` の割り当て：

| fmt | 形式 | 用途 |
|---|---|---|
| `00` | R | レジスタ間演算 |
| `01` | I | 即値演算・メモリ操作 |
| `10` | B | 条件分岐 |
| `11` | J | ジャンプ・実行制御 |

形式ごとに `op` を再利用する。使用しないフィールドは**0を要求する**。未定義の命令符号や予約フィールドの非ゼロ値は不正命令とする。

符号化の基本式（`|` はビットOR、`<<` は左シフト）：

```python
instruction = (
    (fmt << 30) | (op << 25) |
    (A << 22) | (B << 19) | (C << 16) | imm
)
```

例：`ADD R2, R0, R1` は `fmt=0, op=1, A=2, B=0, C=1, imm=0` なので、機械語は **`0x02810000`**。

## 5. 命令セット（全24命令）

記法：`R[A]` はレジスタAの16ビット値、`u16(x) = x mod 2^16`、`s16(x)` はその値を2の補数で解釈した符号付き整数とする。原則として通常命令は `PC ← u16(PC + 4)` へ進む。ジャンプ・分岐・停止命令は個別に定義する。

### 5.1 R形式（fmt = `00`、8命令）

| op | 命令 | 意味 |
|---:|---|---|
| 0 | `MOV A, B` | `R[A] ← R[B]` |
| 1 | `ADD A, B, C` | `R[A] ← u16(R[B] + R[C])` |
| 2 | `SUB A, B, C` | `R[A] ← u16(R[B] - R[C])` |
| 3 | `AND A, B, C` | ビットごとのAND |
| 4 | `OR A, B, C` | ビットごとのOR |
| 5 | `XOR A, B, C` | ビットごとのXOR |
| 6 | `SHL A, B, C` | `R[A] ← u16(R[B] << (R[C] & 0xF))` |
| 7 | `SHR A, B, C` | `R[A] ← R[B] >> (R[C] & 0xF)`（論理右シフト） |

すべて `imm=0`。`MOV` は `C=0` とする。算術結果は16ビットでラップアラウンドする。

### 5.2 I形式（fmt = `01`、6命令）

| op | 命令 | 意味 |
|---:|---|---|
| 0 | `LDI A, imm` | `R[A] ← imm`（16ビットパターンをそのまま代入） |
| 1 | `ADDI A, B, imm` | `R[A] ← u16(R[B] + s16(imm))` |
| 2 | `LD8 A, [B+imm]` | 指定アドレスから1バイト読込、ゼロ拡張 |
| 3 | `LD16 A, [B+imm]` | 指定アドレスから2バイト読込 |
| 4 | `ST8 A, [B+imm]` | `R[A]` の下位1バイトを保存 |
| 5 | `ST16 A, [B+imm]` | `R[A]` の2バイトを保存 |

オフセットは符号付き16ビット。すべて `C=0`。`LDI` の `B` も0。

### 5.3 B形式（fmt = `10`、4命令）

| op | 命令 | 条件 |
|---:|---|---|
| 0 | `BEQ A, B, off` | `R[A] == R[B]` |
| 1 | `BNE A, B, off` | `R[A] != R[B]` |
| 2 | `BLT A, B, off` | `s16(R[A]) < s16(R[B])` |
| 3 | `BGE A, B, off` | `s16(R[A]) >= s16(R[B])` |

分岐成立時は `PC ← u16(PC + 4 + s16(off))`、不成立時は `PC ← u16(PC + 4)`。`off` は**バイト単位**の符号付き相対変位で、4の倍数に限定する。`C=0`。

### 5.4 J形式（fmt = `11`、6命令）

| op | 命令 | 意味 |
|---:|---|---|
| 0 | `JMP off` | `PC ← u16(PC + 4 + s16(off))` |
| 1 | `JAL A, off` | `R[A] ← u16(PC + 4)`、相対ジャンプ |
| 2 | `JR A` | `PC ← R[A]` |
| 3 | `JALR A, B` | `R[A] ← u16(PC + 4)`、`PC ←` 書込前に読み取った `R[B]` |
| 4 | `HALT` | 実行停止 |
| 5 | `TRAP imm` | 実行環境のサービス呼び出し |

`JMP` と `JAL` の `off` はB形式と同じく符号付きバイト変位、4の倍数。`JAL` の `A` はリンク先レジスタ。`JR` と `JALR` のジャンプ先は4バイト境界にある必要がある。

未使用フィールド：`JMP` は `A=B=C=0`、`JAL` は `B=C=0`、`JR` は `B=C=0, imm=0`、`JALR` は `C=0, imm=0`、`HALT` は `A=B=C=imm=0`、`TRAP` は `A=B=C=0`。

`HALT` は停止状態に入り、PCはHALT命令自身の位置のままにする（**実装時の作業上の仮定**）。`TRAP 1` は `R0` の値を符号付き整数として出力し、その後 `PC+4` へ進む。その他のTRAP番号は未定義。

## 6. 命令フェッチと実行時エラー

1. `PC` が4の倍数であることを確認する。
2. `PC` から4バイトをリトルエンディアン順で読み、32ビット命令に復元する。
3. `fmt` と `op` で命令を識別し、レジスタ・即値を取り出す。
4. 命令で定義された状態更新を行う（通常はPCを4進める）。
5. `HALT`、不正命令、アラインメント違反などで停止する。

`PC` の加算は16ビットで折り返す。最後の命令配置可能アドレスは `0xFFFC`。`LD16` / `ST16` の実効アドレスが奇数ならエラー。ジャンプで不正なPCに到達した場合は、次の命令フェッチ時にエラーとする。

**要検討**：不正アクセス時にレジスタやPCへの書き込みをどの時点で確定させるか、エラーを例外・停止コードのどちらで表すか、スタックの範囲外検出をどこが担当するか。

## 7. 関数呼び出しとスタック

- `R6` を戻り先の保存に用いる（ソフトウェア規約）。
- `R7` をスタックポインタとして用いる（ソフトウェア規約）。
- スタックは低アドレス方向へ成長し、16ビット値を2バイト単位で保存する。
- 初期SPとして `0xFFFE` を使う案。これはCPUのハードウェア仕様ではなく起動コード／ローダーの設定。
- `CALL` / `RET` / `PUSH` / `POP` 命令は設けず、通常命令で合成する。

プッシュとポップの例：

```asm
; PUSH R0
ADDI R7, R7, -2
ST16 R0, [R7]

; POP R0
LD16 R0, [R7]
ADDI R7, R7, 2
```

別の関数を呼ぶ関数では、自分の復帰先が上書きされないよう `R6` を保存・復元する。

```asm
callee:
    ADDI R7, R7, -2
    ST16 R6, [R7]   ; 呼出し元への戻り先を保存

    JAL R6, other_function

    LD16 R6, [R7]   ; 元の戻り先を復元
    ADDI R7, R7, 2
    JR R6
```

再帰にはさらに、各呼び出しで保持すべき引数・ローカル変数・途中結果をスタックフレームへ保存する必要がある。引数数が4を超える場合や複数の戻り値についての規約は未決定。

## 8. 動作確認用プログラム案

次は、1から5までの和を求めて表示する、**今回定義した命令だけを使う**アセンブリ例。ラベルはアセンブラがPC相対変位に変換する。

```asm
_start:
    LDI R7, 0xFFFE
    LDI R0, 5
    JAL R6, sum
    TRAP 1
    HALT

sum:
    LDI R1, 0    ; s = 0
    LDI R2, 1    ; i = 1
    LDI R3, 1    ; 定数1
loop:
    BLT R0, R2, done  ; n < i なら終了
    ADD R1, R1, R2
    ADD R2, R2, R3
    JMP loop
done:
    MOV R0, R1
    JR R6
```

期待される出力：`15`。`sum` は他の関数を呼ばない葉関数なので `R6` を退避せずに復帰できる。

## 9. 実装する順序（案）

1. **ISAの意味論を検証**：各命令の入出力とエラー条件をテストにする。
2. **CPUエミュレーター**：レジスタ・PC・メモリと命令の実行ループを実装。
3. **アセンブラ**：命令の符号化・ラベル解決・機械語バイナリの出力。
4. **小さな言語とコンパイラ**：式、変数、分岐、ループ、関数を段階的に追加。
5. **再帰・配列・ランタイム**：スタックフレーム、メモリアクセス、乗算などの補助ルーチンを追加。

## 10. 未確定・要検討事項

- **呼び出し規約（ABI）の確定**：`R4`～`R5` をcallee-savedとするか、保存範囲と引数・戻り値の規約をどうするか。
- **起動時の状態**：初期PC、初期レジスタ値、SPの初期化責任（ローダーか起動コードか）。
- **メモリレイアウト**：コード・静的データ・ヒープ・スタックをどこに置くか。スタックオーバーフロー検出。
- **エラーとトラップ**：不正命令、不正アラインメント、未定義TRAPの挙動、エラー時の状態更新。
- **整数の言語上の意味**：符号付き整数、符号なし整数、オーバーフロー、除算の仕様。
- **比較・分岐**：符号なし大小比較を追加するか（現状は符号付きのみ）。
- **乗算・除算**：ソフトウェアルーチンで開始し、将来の命令追加を検討。
- **即値表現**：アセンブラでの範囲検査、`LDI` に負数を記述した場合の扱い。
- **PC相対の制約**：オフセットが届かない分岐の展開方法（`LDI`＋`JR`など）。
- **命令符号化の改訂可能性**：命令長32ビットと `fmt/op/A/B/C/imm` 配置はv0.1の仮採用であり、実プログラムを作って再評価する。

---

**設計の中心原則**：まず単純な汎用命令で高水準の処理を実現し、コンパイラ・エミュレーターの実装を通じて不足や不自然さが見つかった段階でISAを拡張する。
